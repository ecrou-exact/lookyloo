# CSS organisation

All our stylesheets live in `website/web/static/css/`. There is no build step:
each file is served as-is and protected by SRI.

## Files and load order

`templates/layouts/main.html` loads the stylesheets in this order. Later files
win, so the order matters.

| # | File | Role | Contains |
|---|------|------|----------|
| 1 | Bootstrap 5.3 (bootstrap-flask), `vendor/datatables.min.css`, `vendor/jquery.json-viewer.css` | Third-party | Not edited by us |
| 2 | `css/theme.css` | Design tokens | `--lk-*` custom properties only, light and dark. **The only file with raw colour values.** See [theme.md](theme.md) |
| 3 | `css/bootstrap-bridge.css` | Bootstrap theming | Maps `--lk-*` onto `--bs-*`, and overrides the components where Bootstrap compiles literal colours (buttons, form focus, checkboxes, pagination, nav pills, dropdown and list-group active items, progress bars, accordion) |
| 4 | `css/base.css` | Element defaults | Rules on HTML elements shared by every page: headings, links, focus ring, tables, logo inversion in dark mode |
| 5 | `css/utilities.css` | Shared helpers | Small classes used by templates, Python-generated HTML and JS: `.new-capture-button`, `.help-tip`, `.blur`, `.middleEllipsis*`, `.tooltip` (D3), `.timeline`/`.tl-*`, arrows, collapse toggles, honeypot field |
| 6 | Page CSS (`css/tree.css`, `css/stats.css`) | One page | Loaded only by its page through the `page_styles` block |
| 7 | `css/overrides.css` | Instance hook | Optional, not in git, loaded last so an instance can override anything |

## Adding CSS

- **A colour, font, radius or spacing value** → add or reuse a token in
  `theme.css` (light *and* dark), then use `var(--lk-…)`. Never write a hex,
  `rgb()`, named colour or `light-dark()` anywhere else.
- **A rule for one page** → that page's CSS file, loaded from the page template:

  ```jinja
  {% block page_styles %}
  <link rel="stylesheet" href="{{ url_for('static', filename='css/mypage.css') }}"
        {{get_sri('static', 'css/mypage.css')}}
        crossorigin="anonymous">
  {% endblock %}
  ```

  Use `page_styles`, not `styles`: `page_styles` is placed before the instance
  `overrides.css`, `styles` is not.
- **A reusable piece of UI** → a component with the `lk-` class prefix (to avoid
  collisions with Bootstrap, e.g. `.alert`), documented in its own page in
  `doc/ui/`. `utilities.css` is for the legacy helpers; don't grow it.
- **Changing Bootstrap's look** → `bootstrap-bridge.css`, using tokens.

After touching any file in `static/`, regenerate the SRI hashes:

```bash
poetry run tools/generate_sri.py
```

and reload the website (`kill -HUP` on the gunicorn master, or restart).

## Rules

- Every rule must work in light and dark mode (`data-bs-theme` on `<html>`, set by
  `js/theme_toggle.js`). Test both.
- Class names and IDs are an API: `js/tree.js`, `js/render_tables.js` and Python
  code in `website/web/__init__.py` (`SafeMiddleEllipsisString`, `get_icon`,
  table rows) depend on them. Grep before renaming.
- Some classes come from libraries and won't be found in the repo, e.g.
  `.flashed-messages` is generated by bootstrap-flask's `render_messages()`.
  Don't delete a rule just because grep finds nothing in `website/`.
- No external stylesheets or fonts (CSP): vendor them in `static/`.
- No inline `<style>` blocks; avoid new `style="…"` attributes.

## Known leftovers

- `.tooltip` in `utilities.css` (D3 tooltips) shares its name with Bootstrap's
  tooltip component.
- About 55 inline `style="…"` attributes remain in the templates; they will move
  to CSS as pages are redesigned.
- `tree.css` still styles the tree with its original layout; it will be
  reworked with the capture page.
